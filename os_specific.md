Да, есть специфичные артефакты, уникальные для внутреннего устройства каждой ОС. То, что в Windows называется `HKLM\System\CurrentControlSet`, в Linux будет `/proc` и `sysfs`, а в macOS — демоны `launchd`.

При расследовании живой системы помимо «общего ядра» (сеть, процессы, пользователи) всегда запрашивают эти уникальные для каждой платформы источники.

### 1. Специфика Windows

Здесь критически важен Реестр, Event Logs и механизмы персистентности.

*   **Точки автозагрузки (Persist):**
    *   `Autorunsc.exe` или запрос ключей: `Run`, `RunOnce`, `Winlogon\Shell`, `AppInit_DLLs`, запланированные задачи (schtasks), сервисы и WMI-подписки.
*   **Службы (Services):**
    *   Список драйверов ядра: `driverquery /v` или `sc query type= driver`. Ищутся сервисы со статусом `SERVICE_RUNNING`, но отсутствующим бинарником на диске (признак руткита/ручного маппинга).
*   **Критический реестр:**
    *   `HKLM\System\CurrentControlSet\Control\Lsa` (пакеты аутентификации, security packages — тут сидят кейлоггеры/дамперы паролей).
    *   `HKLM\Software\Microsoft\Windows NT\CurrentVersion\Image File Execution Options` (перехват запуска процессов, отладчики).
*   **AmCache и реестр установленных приложений:**
    *   Данные о приводимых в исполнение файлах, включая те, что уже удалены.
*   **NetBIOS и SMB:**
    *   `nbtstat -c` (кэш имен NetBIOS), открытые сессии `net session / net file`.
*   **Локальные политики и события:**
    *   `auditpol /get /category:*` (включен ли аудит процессов/входа).

### 2. Специфика Linux

Здесь вся информация представлена виртуальными файловыми системами и управлением пакетами.

*   **Псевдо-ФС `/proc/` и `/sys/`:**
    *   `/proc/modules` (lsmod) — загруженные модули ядра (особенно скрытые).
    *   `/proc/<PID>/environ` — переменные окружения конкретного процесса (могут хранить секреты).
    *   `/proc/sys/` — проверка параметров ядра (например, является ли машина маршрутизатором `ip_forward`).
    *   `/proc/version` — точная версия ядра и дистрибутива.
*   **Демоны и автозагрузка:**
    *   Systemd: `systemctl list-units --type=service --state=running`, `systemd-analyze security` (профиль безопасности юнитов).
    *   Cron: системные и пользовательские crontab (`/var/spool/cron/crontabs/`), а также `anacron`.
*   **Управление пакетами (Package Manager):**
    *   `dpkg --verify` или `rpm -Va` — проверка контрольных сумм установленных пакетов для обнаружения измененных бинарников (замена `ps` или `netstat` троянами).
*   **Memory Forensics на уровне ядра:**
    *   Анализ таблицы системных вызовов (`sys_call_table`) на хуки (редко доступно из юзерспейса без спец. модулей).
*   **Атрибуты безопасности:**
    *   SELinux (`getenforce`, контексты), AppArmor (`aa-status`).

### 3. Специфика macOS

Гибридная система, где UNIX база перекрыта фреймворками Apple и запуском через `launchd`.

*   **Launch Agents and Daemons:**
    *   `/System/Library/LaunchDaemons`, `/Library/LaunchAgents` и пользовательские пути. Сбор информации через `launchctl list` (показывает PID и last exit code).
*   **Технология Gatekeeper и подписи:**
    *   `spctl --assess --verbose /path/to/app` — проверка, пройдет ли файл Gatekeeper.
    *   `codesign -dvvv /path/to/app` — верификация кодовой подписи (вредоносные фреймворки обычно без подписи).
*   **Quarantine Events (База карантина):**
    *   Чтение БД `~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2`. Содержит URL, откуда был скачан файл, агента загрузки и дату — ключевой источник для идентификации фишинга.
*   **Kernel Extensions (Kexts):**
    *   `kextstat` — список загруженных расширений ядра (с версий High Sierra+ требуется одобрение пользователя в Security & Privacy).
*   **Управление конфигурацией (Managed Settings):**
    *   `profiles -L` — установленные конфигурационные профили (MDM/конфигурации, скрывающие ПО).
*   **Унифицированные логи (Unified Logging):**
    *   Утилита `log show` — архитектура логов Apple, заменяющая старые syslog.

**Резюме:** Универсальный сборщик (типа UAC, Velociraptor или GRR) обязательно качает и универсальный срез (процессы/сеть), и специфичные для платформы артефакты, так как руткиты обычно маскируются именно на уровне специфичного API ОС.
